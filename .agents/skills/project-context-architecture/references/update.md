# Update workflow

1. **Select evidence.** Define the conversation or project changes in scope. If history is unavailable or compressed, say so; use only available evidence. Identify durable facts, decisions, corrections, risks and open questions, distinguishing observations from inference and planned behavior. Check relevant sources and existing context using targeted searches.
2. **Filter and place.** Keep changes that affect discovery, ownership, architecture, contracts, safety, or a recurring trap. A small change or bug fix can still matter if it corrects a misleading or safety-critical claim; a large change need not produce new context if already covered. Exclude ephemeral details, secrets, unnecessary sensitive data and unsupported generalizations. For each candidate choose no change, amend an existing leaf, repair routing, add a connected leaf, or defer verification. Preserve version and environment limits.
3. **Apply only authorized changes.** Edit the smallest existing node and its direct route; add a leaf only when independently useful and connect it through the relevant domain index. Assess touched nodes for growth and apply the [bootstrap split-and-route rules](bootstrap.md#split-and-route-when-context-grows), including thresholds, link repair and migration permissions. Preserve established instructions and unrelated material. Report contradictions or decisions needing broader changes rather than guessing. If no edit is authorized, present the proposals only.
4. **Verify.** Check affected links, trace changed intent routes to real owners, and compare changed claims with source evidence. Update any existing context map or freshness register only for the checked scope; mark uncertainty and uncommitted evidence honestly. Report applied changes, deferred items, and missing evidence.

Done when each candidate has a reasoned disposition and authorized edits have been checked, or no change is justified.
