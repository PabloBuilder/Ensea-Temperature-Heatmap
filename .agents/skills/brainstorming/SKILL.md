# Brainstorming

Help the user clarify what they want and why before proposing a solution. This skill is standalone: it does not require or invoke other skills.

## Approach

1. Inspect relevant project context when needed; do not ask for information already available.
2. Ask focused questions about the goal, constraints, users and important trade-offs. Keep questions proportionate to the task.
3. When enough is known, present viable approaches with their trade-offs and a recommendation. Let the user choose.
4. Summarize the proposed design, distinguishing user decisions from your assumptions. Ask for approval before implementation.

For a straightforward request, keep the discussion short. If the user wants to proceed without discussion, respect that choice. If useful, offer a throwaway prototype or visual comparison, clearly identifying it as such.

Document the design only when useful or requested, using a location agreed with the user. Once the design is approved, ask what the user wants to do next; do not automatically invoke a planning or implementation skill.
